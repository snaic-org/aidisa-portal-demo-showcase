Processing Pipeline

Feedback is received first and queued. One backend worker processes each record through every stage. Charts, alerts and assignment only update after the last stage finishes.

AI · LLMSeverity & NER – a large language model with few-shot prompts rates severity and pulls out incident keywords and locations from free text (emails, chats, call notes).
AI · RoBERTaSentiment index – TranSent-X (Transport Sentiment Experience), our RoBERTa model fine-tuned on transport feedback, scores each report from 1 Very Negative to 5 Very Positive. The Sentiment Dashboard averages these scores into the Sentiment Intensity index.
ML · SVCCategory – a support vector classifier trained on past cases assigns the main category.
Rule-basedPre-processing & assignment – deterministic cleaning, then routing by team, skill, leave and workload.

How AIDISA handles a piece of feedback

  1. Receive: feedback arrives from IFS, web forms or social media and joins a queue.
  2. Process: a worker runs pre-processing, the severity model, keyword/NER extraction and category classification.
  3. Assign: the case is routed to a team and skill, then given to the least-loaded available staff member.
  4. Detect surges: reports the AI rated High severity (adjustable) are counted per keyword; when a keyword reaches the threshold within the window, a surge alert is raised.

Event surge detection

Are enough serious reports about the same thing coming in right now? Settings come from the Event Surge Tracker.

How a surge is decided

Count
Which AI severity ratings count. Default is High only, so routine complaints never trigger a surge. Tick Medium to also watch service issues such as lift faults or no aircon.
Window (min)
How far back “right now” looks. Reports in the last this-many minutes are counted.
Threshold
How many of those reports about the same keyword raise an alert. Lower it to be warned sooner; raise it to cut noise.
